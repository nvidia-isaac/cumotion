Release Notes#

Release 2.0.0 - November 23, 2026#

What’s New#

  • TrajectoryOptimizer now represents each trajectory as a uniform cubic B-spline instead of a dense sequence of knot points. Costs and constraints are evaluated with the spline’s analytical derivatives at densely sampled points, and the number of spline spans is configured with the new trajopt/num_spans parameter. The activation distances of the c-space velocity, acceleration, and jerk limit penalties are now specified relative to each limit, using the new relative_activation_distance parameters of those penalties.

    The trajectory returned by Results::trajectory() is now self-consistent: the velocity, acceleration, and jerk reported by Trajectory::eval() are the time derivatives of its position, whereas previously each derivative was interpolated independently. Position, velocity, and acceleration are continuous, and jerk is piecewise constant. Each returned trajectory is uniformly time-scaled to the shortest duration for which its c-space velocity, acceleration, and jerk stay within their limits over the entire trajectory.

    If the initial optimization finds no valid trajectory, the retiming iterations now continue to optimize every candidate, so the solve can still succeed. As a result, solves that ultimately fail run every retiming iteration and may take longer.

  • TrajectoryOptimizer is now faster and produces shorter trajectories. Compared to cuMotion 1.1 on the MotionBenchMaker benchmark for the Franka Panda (1,600 planning problems per platform, split evenly between task-space and c-space targets), average planning time dropped from 96 ms to 41 ms (2.4x faster) on a GeForce RTX 5090 and from 297 ms to 234 ms (1.3x faster) on Jetson AGX Thor. Average trajectory duration is 15% shorter on both platforms (1.57 s vs. 1.85 s), and the success rate increased from 99.4% to 99.9%. Averages are computed over successful plans.

  • The PathPlanner has been added to the library. This class improves upon and replaces MotionPlanner for path planning tasks. It is fully GPU-accelerated and is typically between 10 and 100 times faster, depending on the problem and robot.

    The PathPlanner drops support for task-space targets. The recommended flow for task-space targets is to use CollisionFreeIkSolver to generate a set of collision-free c-space positions that achieve the task-space constraints, and to pass all solutions to the PathPlanner, which will plan to at least one c-space target.

    The PathPlanner is fully integrated into TrajectoryOptimizer as the initial phase for problems without task-space path constraints, quickly finding collision-free paths that seed the trajectory optimization. This results in a significant improvement to outlier optimization times.

  • The new RobotDescriptionBuilder API lets applications construct a RobotDescription directly in C++ or Python. It accepts programmatically specified kinematics and collision geometry, eliminating intermediate URDF and XRDF files and simplifying integration with custom robot-model formats.

  • TrajectoryOptimizer now provides improved convergence for task-space path constraints. For typical problems, the maximum positional deviation is now under 4 mm. The trajopt/task_space_path_constraint_position_tolerance and trajopt/task_space_path_constraint_orientation_tolerance parameters are now publicly exposed through TrajectoryOptimizerConfig, allowing applications to configure position and orientation constraint tolerances.

  • The following parameters have been added to TrajectoryOptimizerConfig:

    • trajopt/num_spans

    • trajopt/pbo/cost/cspace_velocity_limit_penalty/relative_activation_distance

    • trajopt/pbo/cost/cspace_acceleration_limit_penalty/relative_activation_distance

    • trajopt/pbo/cost/cspace_jerk_limit_penalty/relative_activation_distance

    • trajopt/lbfgs/cost/cspace_velocity_limit_penalty/relative_activation_distance

    • trajopt/lbfgs/cost/cspace_acceleration_limit_penalty/relative_activation_distance

    • trajopt/lbfgs/cost/cspace_jerk_limit_penalty/relative_activation_distance

    • trajopt/task_space_path_constraint_position_tolerance

    • trajopt/task_space_path_constraint_orientation_tolerance

    • path_planner/random_seed

    • path_planner/max_num_segments_per_forest

    • path_planner/num_validation_checks_per_extension

    • path_planner/step_size

    • path_planner/num_spheres_per_validation_iteration

    • path_planner/min_extension_length

    • path_planner/num_shortcut_iterations

    • path_planner/max_iterations

    • path_planner/post_initial_solve_maximum_iterations

    See cumotion::TrajectoryOptimizerConfig::setParam() for detailed documentation of the trajectory optimizer parameters. The path_planner/ parameters tune the integrated PathPlanner and correspond to the parameters documented by cumotion::PathPlannerConfig::setParam(), with the path_planner/ prefix added. See that function’s documentation for detailed descriptions, default values, constraints, and tuning recommendations.

  • The default trajopt/ parameters of TrajectoryOptimizerConfig have been retuned for the B-spline representation, including the L-BFGS cost weights, iteration counts, and timestep scaling factors. See cumotion::TrajectoryOptimizerConfig::setParam() for the current default values.

  • Added support for Jetson Orin with JetPack 7.2.1 (CUDA 13.2), in addition to JetPack 6.2.1 (CUDA 12.6). The packages for Jetson Thor (JetPack 7.2), x86_64 Linux (Ubuntu 24.04), and Microsoft Windows are now built with CUDA 13.2, and DGX Spark (DGX OS 7.2) has its own CUDA 13.0 package. See Getting Started for the full support matrix.

  • Updated urdfdom to 5.1.0 and urdfdom_headers to 2.1.0, and replaced TinyXML with TinyXML-2 11.0.0.

Breaking Changes#

  • The x86_64 packages now require an NVIDIA GPU of the Ampere generation or later. Turing GPUs (e.g., GeForce RTX 2080) are no longer supported. The x86_64 Ubuntu 22.04 (CUDA 12.6) package has been discontinued, and the Linux packages now require GCC 13 or later (GCC 11.4 or later on Jetson Orin with JetPack 6). See Getting Started for the full support matrix.

  • Trajectory optimizer YAML configuration files now require format_version: 2.0 together with format: cumotion_trajopt. All other format_version values, including legacy 1.0, are unsupported and fail to load. See What’s New and Deprecation Notice for the parameters added and deprecated between format versions, and the list of removed items below for the parameters that are no longer accepted.

    The cuMotion library version 2.0 config parser follows the behavior documented by cumotion::TrajectoryOptimizerConfig::setParam() for deprecated parameters, even though they are not part of the TrajectoryOptimizerConfig 2.0 format version. These parameters are accepted with a warning and then applied, mapped to their replacements, or safely ignored, as described in Deprecation Notice. This parsing behavior is tied to the cuMotion library version (rather than the TrajectoryOptimizerConfig 2.0 format version) and may be removed in a future release. Removed parameters, such as trajopt/num_knots_per_trajectory, are not accepted: a configuration file that contains one fails to load.

  • The default L-BFGS cost weights of TrajectoryOptimizer (trajopt/lbfgs/cost/) have changed by up to several orders of magnitude for the B-spline representation. For example, trajopt/lbfgs/cost/world_collision_penalty/weight changed from 1e6 to 8.5e2, and trajopt/lbfgs/cost/cspace_velocity_limit_penalty/weight changed from 1e3 to 1e5. Custom values tuned for cuMotion 1.x are unlikely to transfer and should be re-tuned, starting from the new defaults. In addition, the absolute activation_distance parameters of the c-space velocity, acceleration, and jerk limit penalties are now ignored, as described in Deprecation Notice.

The following items have been removed in this release:

  • The single-target interface in RMPflow (RmpFlow::setEndEffectorPositionAttractor(), etc.) has been removed in favor of the new multi-target interface (RmpFlow::addTargetFrame(), RmpFlow::setPositionTarget(), etc.).

  • WorldInspector::distancesTo() now requires distances to be input by reference. The overload supporting pointer input has been removed.

  • The deprecated “goalset” interface in CollisionFreeIkSolver (CollisionFreeIkSolver::solveGoalset(), TranslationConstraintGoalset, OrientationConstraintGoalset, and TaskSpaceTargetGoalset) has been removed in favor of CollisionFreeIkSolver::solveArray() with TranslationConstraintArray, OrientationConstraintArray, and TaskSpaceTargetArray.

  • The TrajectoryOptimizerConfig parameter trajopt/num_knots_per_trajectory has been removed, since trajectories are no longer represented by a dense sequence of knot points. It is not mapped to any other parameter; use trajopt/num_spans to configure the trajectory discretization instead. Setting it with cumotion::TrajectoryOptimizerConfig::setParam() logs a non-fatal error and returns false, and CreateTrajectoryOptimizerConfigFromFile() logs a non-fatal error and returns nullptr for any configuration file that contains it.

Deprecation Notice#

The following items are deprecated and will be removed in the next major release:

  • The MotionPlanner and MotionPlannerConfig classes, along with the free functions that create them (CreateMotionPlannerConfigFromFile(), CreateDefaultMotionPlannerConfig(), and CreateMotionPlanner()) have been deprecated in favor of PathPlanner and PathPlannerConfig. The Create*() functions log a deprecation warning to the console on every call, and their C++ declarations are marked deprecated so that client code also gets a compile-time warning.

    The PathPlanner drops support for task-space targets, so MotionPlanner::planToTranslationTarget() and MotionPlanner::planToPoseTarget() have no direct replacement. The recommended flow for task-space targets is to use CollisionFreeIkSolver to generate a set of collision-free c-space positions that achieve the task-space constraints, and to pass all solutions to PathPlanner::planToCSpaceTargets().

  • The following TrajectoryOptimizerConfig parameters are deprecated. They remain accepted with a warning and use these fallback behaviors:

    • enable_self_collision and enable_world_collision still take effect.

    • trajopt/num_geometric_planning_attempts is safely ignored because it no longer has any effect.

    • trajopt/geometric_planning/max_iterations is mapped to path_planner/max_iterations by dividing the provided value by 10. If both parameters are specified in a configuration file, path_planner/max_iterations takes precedence. Prefer setting path_planner/max_iterations directly.

    • The absolute activation_distance parameters of the c-space velocity, acceleration, and jerk limit penalties are safely ignored because they no longer have any effect. Use the relative_activation_distance parameters of the same penalties instead:

      • trajopt/pbo/cost/cspace_velocity_limit_penalty/activation_distance

      • trajopt/pbo/cost/cspace_acceleration_limit_penalty/activation_distance

      • trajopt/pbo/cost/cspace_jerk_limit_penalty/activation_distance

      • trajopt/lbfgs/cost/cspace_velocity_limit_penalty/activation_distance

      • trajopt/lbfgs/cost/cspace_acceleration_limit_penalty/activation_distance

      • trajopt/lbfgs/cost/cspace_jerk_limit_penalty/activation_distance

    All deprecated parameters will be removed in a future release.

Known Issues#

  • A CPU memory leak is exposed when adding and removing obstacles to a world. Each cycle adding and removing an obstacle will grow memory usage, with impacts most noticeable for SDF obstacles. Updating values of an existing SDF does not contribute to this memory leak.

  • Open3D is used for visualization in some of the Python examples. Because Open3D is not currently available from PyPI for the aarch64 architecture, these examples will lack visualization when run on NVIDIA Jetson or NVIDIA DGX Spark.

Release 1.1.0 - April 10, 2026#

What’s New#

  • Added support for NVIDIA DGX Spark.

  • Added support for Microsoft Windows.

  • Added wheel files for all actively-supported Python versions (currently 3.10 through 3.14) for all platforms.

  • Added support for batch mode in collision-free IK.

  • Added multi-target support for RMPflow.

  • Added self-collision support for geometric motion planning. Self-collision checking is now the default for both MotionPlanner and geometric planning within the TrajectoryOptimizer pipeline.

  • Improved performance of nearest-neighbor queries for geometric planning. This optimization is only enabled when using unweighted distance_metric_weights (i.e., a vector of all ones). This is the default, generally-recommended setting for MotionPlanner.

  • Improved performance of trajectory optimization.

  • Updated default parameters for collision-free IK and trajectory optimization to improve success rates and convergence.

  • Extended WorldInspector to support querying obstacle pose() and isEnabled() status.

  • Enabled Python interface compatibility with NumPy 2.x by updating to pybind11 version 3.0.1.

  • Eliminated all internal use of CUDA Unified Memory. On Jetson Orin, this enables cuMotion to run in the same process as other threads making simultaneous use of CUDA. Platforms with full Unified Memory support (i.e., x86_64 and Jetson Thor) are unaffected by this change.

Deprecation Notice#

The following items are deprecated and will be removed in the next release:

  • CollisionFreeIkSolver::solveGoalset() and related target constructors have been deprecated in favor of CollisionFreeIkSolver::solveArray() and related target constructors. The newly added solveArray() supports both batch mode (i.e., multiple problems with a single target per problem) and goalset mode (i.e., a single problem with multiple targets). Goalset batch mode support (i.e., multiple problems, each with multiple targets) will be added in a future release.

  • The single-target interface in RMPflow (RmpFlow::setEndEffectorPositionAttractor(), etc.) has been deprecated in favor of the new multi-target interface (RmpFlow::addTargetFrame(), RmpFlow::setPositionTarget(), etc.).

  • WorldInspector::distancesTo() now expects distances to be input by reference. A deprecated overload supports pointer input.

  • The MotionPlannerConfig parameter cuda_tree_params/max_num_nodes has been deprecated and will now be ignored (with warning). The size of CUDA-accelerated trees is no longer directly bounded and cuda_tree_params/max_num_nodes will be ignored.

Known Issues#

  • A CPU memory leak is exposed when adding and removing obstacles to a world. Each cycle adding and removing an obstacle will grow memory usage, with impacts most noticeable for SDF obstacles. Updating values of an existing SDF does not contribute to this memory leak.

  • Open3D is used for visualization in some of the Python examples. Because Open3D is not currently available from PyPI for the aarch64 architecture, these examples will lack visualization when run on NVIDIA Jetson or NVIDIA DGX Spark.

Release 1.0.0 - December 19, 2025#

What’s New#

  • Improved performance of both collision-free IK and trajectory optimization.

  • Added experimental support for segmenting (masking) out the contribution of a robot from a depth image. This functionality is currently only exposed in C++ and only supports depth image buffers stored on the host (i.e., in CPU memory).

  • Eliminated all internal use of the default CUDA stream.

Known Issues#

  • On Jetson Orin, cuMotion should not be run in the same process as other threads making simultaneous use of CUDA. This restriction is related to the manner in which cuMotion uses CUDA Unified Memory and will be lifted in a future release.

  • Open3D is used for visualization in some of the Python examples. Because Open3D is not currently available from PyPI for the aarch64 architecture, these examples will lack visualization when run on NVIDIA Jetson.
